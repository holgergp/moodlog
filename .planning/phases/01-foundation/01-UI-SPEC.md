## Spacing Scale

Declared values (multiples of 4). Tailwind v4 ships this scale natively — no
`tailwind.config.js` override required; tokens map 1:1 to Tailwind utilities.

| Token | Value | Tailwind util | Usage |
|-------|-------|---------------|-------|
| xs | 4px  | `p-1 / gap-1`   | Icon-to-label gap, inline badge padding |
| sm | 8px  | `p-2 / gap-2`   | Compact control spacing, chip row gaps |
| md | 16px | `p-4 / gap-4`   | Default vertical rhythm between form sections |
| lg | 24px | `p-6 / gap-6`   | Section padding on the entry form |
| xl | 32px | `p-8 / gap-8`   | Major screen padding; gap between form and footer CTA |
| 2xl | 48px | `p-12 / gap-12` | Onboarding step padding; vertical rhythm between major blocks |
| 3xl | 64px | `p-16 / gap-16` | Top-of-screen breathing room on tall viewports |

**Touch targets:** All interactive controls (scale buttons 1-5, segmented
controls, date chip, chips, primary save button) have a hit area of at least
**44×44px** (iOS HIG minimum). This is an exception to the 4-point grid — a
button may be `h-11` (44px) visually even though 44 isn't on the scale above.
shadcn-svelte primitives hit this by default.

**Exceptions:** `44px` touch-target minimum for all inputs — overrides any smaller
visual height. Otherwise, no exceptions.

## Typography

Mobile-first. Sizes chosen to keep the entry form fully visible on an iPhone SE
(375×667) without scroll for the core fields, and to comfortably hit 16px for
any `<input>` to prevent iOS Safari auto-zoom-on-focus.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px | 400 (regular)  | 1.5 | Default paragraph, helper text, autocomplete options, onboarding copy |
| Label | 14px | 600 (semibold) | 1.4 | Field labels ("Mood", "Energy", "Workload", "Social split", "People"), scale-tick numbers |
| Heading | 20px | 600 (semibold) | 1.3 | Screen title ("Tonight"), date chip active label, onboarding step titles |
| Display | 28px | 600 (semibold) | 1.2 | First-open welcome heading ("Add to Home Screen") |

**Weight discipline:** Exactly two weights in use — `400` regular and `600`
semibold. No `500`, no `700`. No italics except for the MNAR warning copy in
later phases (not in Phase 1).

**Input font-size floor:** Any `<input>` or `<textarea>` that accepts text
(people-tag input, reminder-time picker) uses **16px minimum** to suppress
iOS Safari's auto-zoom behaviour on focus.

## Color

Palette follows the 60/30/10 rule with a neutral-dominant surface, elevated
secondary, and a single restrained accent. Values target **WCAG AA contrast
(≥4.5:1) for all text** and support `prefers-color-scheme: dark` via Tailwind
v4 `@theme` tokens.

Light mode (default) values below; dark mode is a symmetric inversion generated
from the same token names.

| Role | Value (light) | Value (dark) | Usage |
|------|---------------|--------------|-------|
| Dominant (60%)   | `#FAFAF9` (stone-50)    | `#0C0A09` (stone-950) | App background, form page surface |
| Secondary (30%)  | `#FFFFFF` / `#E7E5E4` borders (white cards on stone) | `#1C1917` (stone-900) card / `#292524` border | Form field cards, segmented-control backgrounds, date-chip surface, onboarding sheets |
| Accent (10%)     | `#0F172A` (slate-900)   | `#F1F5F9` (slate-100) | Primary "Save"/"Update" button fill, selected-state background on the 1-5 scale dots, active segmented-control segment, active chip fill |
| Destructive      | not used in Phase 1 (see note) | — | Reserved only — no destructive actions are shipped in Phase 1 |

**Accent reserved for:**
1. Primary CTA button fill ("Save" / "Update")
2. Selected 1-5 scale dot (mood and energy): filled dot in accent, unselected dots are outline only
3. Active segment of workload segmented control (light/moderate/heavy)
4. Active segment of social-split segmented control
5. Selected people-tag chip background (chip ring accent when toggled on)
6. Calendar-picker selected-date highlight

**Accent explicitly NOT used for:**
- Text links in body copy (use underlined stone-900 text instead)
- Field borders at rest (stone-300)
- Form labels
- "Install to Home Screen" banner background (secondary surface only)
- Focus rings — focus uses a dedicated `focus-visible` outline (`ring-2 ring-slate-900/40`) which appears everywhere but is distinct from accent

**Destructive color note:** Phase 1 ships **no destructive actions** (no delete
entry, no delete tag — see CONTEXT.md §Deferred Ideas). The destructive token
is reserved for later phases; a placeholder token `#B91C1C` (red-700) is
registered in `@theme` so future phases don't introduce a new value, but it is
not referenced by any Phase 1 component.

**Negative-affect neutrality (PITFALLS #11):** Missing-day UI, low-mood values,
and low-energy values are **never** rendered in red, orange, or any
shame-signalling hue. A mood-1 button and a mood-5 button are visually
identical when unselected and identical when selected — only position encodes
the value. There is no "bad-day red" anywhere in Phase 1.

## Copywriting Contract

Tone: observational, present-tense neutral, no moralising adjectives ("good",
"bad"), no gamification ("streak", "keep it up", "don't break it"), no
apology framing for missing days (PITFALLS #2, #11, CONTEXT.md D-14).

| Element | Copy |
|---------|------|
| Primary CTA (new entry) | **Save** |
| Primary CTA (existing entry) | **Update** (per D-11) |
| Form screen title | **Tonight** (when date chip = today and no entry) / **{weekday}, {D mmm}** when date chip is a past date (e.g. "Tuesday, 16 Apr") |
| Date chip label | **Today**, or short format `Tue, 16 Apr` for past dates |
| Mood prompt | **How was today overall?** (per PITFALLS #3 — past-tense, whole-day framing, NOT "How do you feel?") |
| Energy prompt | **Energy** (label only — no adjective prompt; scale is self-explanatory) |
| Workload prompt | **Workload** (label) + three segment labels: **Light** / **Moderate** / **Heavy** |
| Social-split prompt | **Social** (label) + three segment labels: **Mostly alone** / **Mixed** / **Mostly with others** (verbatim per CONTEXT.md §Specifics) |
| People prompt | **People** (label). Input placeholder: **Add a person…** |
| People — empty chip row hint | **No one yet** (small helper text under the input, stone-500; appears only before any tag exists in the whole app) |
| People — "create new" row | **+ Create "{typed text}"** (shown at bottom of filtered list when no case-insensitive match) |
| Save feedback toast | **Logged.** (terminal period, auto-dismiss in ~1.5s — per D-03, no tap needed) |
| Update feedback toast | **Updated.** |
| Empty state heading (entry for today not yet saved) | **Tonight** (title itself IS the empty state — there is no separate "no entries yet" screen, because the form IS the home; per D-02) |
| Empty state body | (none — the form IS the body; no explainer copy beyond the field labels) |
| Backfill empty-day state | Same neutral form as any other day. **No** badges like "missed", **no** prompts like "fill this in" (per D-14, PITFALLS #11) |
| Error — save failed locally | **Couldn't save. Check storage permissions and try again.** (rare — IndexedDB write failure; actionable) |
| Error — notification permission denied | **Reminders are off. You can enable them in your browser settings.** (shown once in onboarding; dismissible) |
| Onboarding step 1 heading | **Add MoodLog to your Home Screen** |
| Onboarding step 1 body (iOS) | **Tap the Share icon, then "Add to Home Screen". This keeps your entries safe — Safari clears data from regular tabs after a week.** |
| Onboarding step 1 body (Android/Chrome) | **Tap the menu, then "Install app". This keeps your entries safe across restarts.** |
| Onboarding step 1 "Skip" button | **Skip for now** (per D-17) |
| Onboarding step 2 heading | **When should we check in?** |
| Onboarding step 2 body | **We'll send one reminder at this time. You can change it later.** |
| Onboarding step 2 default time | **21:00** (per D-19) |
| Onboarding step 2 confirm button | **Continue** |
| Non-installed iOS banner | **Install to Home Screen to enable reminders.** (verbatim per CONTEXT.md §Specifics; dismissible per D-18) |
| Notification body | **Log today — how was it?** (verbatim per CONTEXT.md §Specifics, D-20) |
| Destructive confirmation | **(none shipped in Phase 1)** |

**Banned phrases (must not appear anywhere in Phase 1 UI):**
- "Streak", "X-day streak", "don't break", "keep it up"
- "Good day", "bad day", "great", "rough" (as a rating label)
- "Average mood", "avg", any decimal number rendered from mood/energy data
- "How do you feel?" (present-tense; PITFALLS #3)
- "Missed!", "You skipped", "Fill in the gap"
- Any exclamation mark in system feedback (the app's voice is calm, not excited)

## Interaction Contract

These are the interaction guarantees the executor must deliver. The checker will
verify against them.

1. **Tap-count budget:** From cold app open to a saved entry, no flow requires
   more than **4 taps** (PITFALLS #1, CONTEXT.md Canonical Refs). A typical
   path: open app → tap mood → tap energy → tap Save = 3 taps + implicit scroll.
2. **No required fields.** Save is always enabled on every render (D-08). Empty
   fields persist as `null` in Dexie.
3. **No confirmation modals** between tapping Save and the toast (D-03).
4. **Toast is non-blocking**: dismisses itself in ~1.5s; the user can scroll,
   tap the date chip, or navigate away at any moment (D-03).
5. **Date-chip single-surface pattern** (D-11, D-12): tapping the chip opens a
   Popover-hosted calendar; selecting a past date re-hydrates the form with
   that date's saved values (if any) and changes the CTA label from **Save**
   to **Update**.
6. **Future dates disabled** in the calendar picker (D-13). Past dates have no
   lower bound.
7. **Autocomplete semantics for tags** (D-07, D-09): typing filters
   case-insensitively by the stored lowercase key while preserving the display
   name. The "+ Create "{text}"" row appears only when no exact
   case-insensitive match exists against the filtered set.
8. **No emoji in any input control** (D-04, D-05, D-06). Lucide icons are
   allowed for interface affordances (calendar, share, menu) but not for
   affect/value communication on the scale.
9. **Focus-visible rings** render on every focusable control (keyboard users,
   accessibility) using `focus-visible:outline-none focus-visible:ring-2
   focus-visible:ring-slate-900/40` (light) / `ring-slate-100/40` (dark). This
   is distinct from the accent fill so the two states never blur.
10. **Native input sizing for zoom suppression:** text inputs use `text-base`
    (16px) minimum.
11. **Keyboard behaviour on mobile:** the people-tag input is the only text
    input on the form. When focused, the page must not jump or re-layout — use
    `visualViewport`-safe scroll anchoring (no `position: fixed` footers that
    the iOS keyboard pushes over).
12. **Reduced motion:** toast appearance and calendar popover respect
    `prefers-reduced-motion` — collapse transitions to an opacity fade (<120ms)
    when the setting is on.

## Accessibility Contract

| Requirement | How Phase 1 meets it |
|-------------|----------------------|
| WCAG AA text contrast (≥4.5:1 body, ≥3:1 large) | Token palette selected against stone/slate combinations; checker to run contrast audit |
| 44×44px touch targets | Enforced in spacing exceptions; shadcn-svelte primitives comply |
| Keyboard navigable | Every control reachable by Tab; focus-visible rings distinct from accent |
| Screen-reader labelling | Every input has an associated `<Label>`; scale buttons use `aria-label="Mood {n} of 5"`; segmented controls use `role="radiogroup"` with per-segment `aria-label` |
| Motion sensitivity | Reduced-motion path on all transitions |
| No colour-only signal | Selected state uses both colour (accent fill) AND shape change (outline → filled dot; outline → solid segment) — a colourblind user reads the selection from shape alone |
| No auto-playing sound or autofocus traps | No audio; autofocus is off on all fields (the user taps where they want to start; avoids iOS keyboard popping on load) |

## Registry Safety

| Registry | Blocks Used | Safety Gate |
|----------|-------------|-------------|
| shadcn-svelte official | `button`, `input`, `label`, `popover`, `calendar`, `toast` (sonner), `toggle` / `toggle-group` | Not required — first-party registry; view-passed by project policy |
| (third-party registries) | none | not applicable |

No third-party registries declared for Phase 1. If the planner later adds one
(e.g. a specialised time-picker block), the ui-researcher vetting gate must
run on the block source before it enters this table.

**PITFALLS #12 enforcement:** Any registry block that introduces a network
`fetch`, a `<script src="…">` to a non-first-party origin, or an environment
variable read must be rejected during the vetting gate regardless of its UI
utility. Registry hygiene and the CSP allowlist are aligned from day one.
