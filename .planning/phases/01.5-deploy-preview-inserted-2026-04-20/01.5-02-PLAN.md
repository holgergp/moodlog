<pitfalls>
**P-5 (RESEARCH Pitfall 1): First main-branch deploy is throwaway.**
When Netlify is first linked via OAuth, it auto-builds the current `main` tip. At Phase 1.5 start, main does NOT yet have netlify.toml or the adapter swap (those live only on `phase-1.5-deploy-preview`). The first production-URL deploy will either fail (adapter-auto can't detect the host, or misconfigures) or produce wrong output. This is EXPECTED — ignore the production URL until the PR merges. The PR-preview URL is the authoritative Phase 1.5 validation target.

**P-6 (RESEARCH Pitfall 2 + 3): iOS notification UAT requires foreground + installed PWA.**
- `setInterval` is paused/throttled when iOS backgrounds the app. UAT #1 MUST be run with the PWA in the foreground for the full ~2-minute wait between setting reminder_time and the fire event. Setting a reminder and locking the phone will NOT fire.
- Notification permission prompts on iOS 16.4+ require an INSTALLED PWA AND a direct user gesture. UAT #1 procedure: install first, THEN grant permission from onboarding step 2.

**P-7 (RESEARCH Pitfall 5): preview-vs-production origin difference for IndexedDB.**
`deploy-preview-N--{slug}.netlify.app` and `{slug}.netlify.app` are DIFFERENT origins. IndexedDB entries logged on the preview URL will NOT carry over to production. HUMAN-UAT #3 (7-day eviction survival) MUST be scheduled against the PRODUCTION URL after merge, NOT the preview URL (which may be garbage-collected when the PR closes). Document the calendar reminder against `{slug}.netlify.app`, not the preview.

**P-8 (RESEARCH Pitfall 6): verify precache manifest survived production build.**
The workbox `__WB_MANIFEST` injection depends on Vite's tree-shaking behaviour which can vary across Node versions and esbuild minor versions. Netlify's build container is a different environment from the developer's local. After first Netlify build succeeds, curl the deployed service-worker.js and count `"revision"` occurrences — must be 20+, matching Plan 01 Task 1.3's local baseline.

**P-9 (Assumption A1): iPhone iOS version.**
If the user's iPhone is on iOS < 16.4, UAT #1 notification permission prompt will not appear (Apple gated web push to iOS 16.4+ in installed PWAs). This is an environmental constraint, not a regression. Confirm iOS version at UAT time; if pre-16.4, mark UAT #1 as "blocked by iOS version" and document rather than iterating on code.
</pitfalls>
