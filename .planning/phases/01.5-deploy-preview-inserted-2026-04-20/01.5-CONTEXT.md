# Phase 1.5: Deploy preview - Context

**Gathered:** 2026-04-21

<domain>
## Phase Boundary

Deploy the Phase 1 foundation (entry form, PWA, local Dexie, EN+DE i18n, notifications) to a throwaway Netlify preview URL so PWA install, notification permission, and `navigator.storage.persist()` can be validated on real iOS Safari before Phase 2's auth/export work begins.

**In scope:** adapter swap (`adapter-auto` → `adapter-netlify`), `netlify.toml` for build + headers, Netlify site creation, branch-based auto-deploy hook, first successful deploy, verification of the three open HUMAN-UAT items from Phase 1.

</domain>

<decisions>
## Implementation Decisions

### Git trigger strategy
- **D-01:** Netlify watches GitHub repo `holgergp/moodlog`. Merges to `main` deploy to production (`moodlog.netlify.app` or chosen slug). Every PR automatically gets its own `deploy-preview-{n}--{site}.netlify.app` URL.
- **D-02:** Netlify's auto-deploy only fires when commits reach `origin/main` or a PR branch on origin. Given the global hook that blocks direct push to main, main-commits arrive via merged PRs. Local main commits stay invisible to Netlify until a PR lands.
- **D-03:** Phase 1.5 itself will be the first PR. Development of Phase 1.5 happens on a feature branch pushed to origin, producing the first PR-preview URL. That URL is used to run the three HUMAN-UAT items before the PR merges.

### Build output shape
- **D-04:** Use the default `@sveltejs/adapter-netlify` behavior (serverless-capable, prerenders what it can, generates functions for any `+page.server.ts`). Do NOT force prerender-all.
- **D-05:** Phase 2 will decide whether auth runs client-side (stay effectively static) or via a serverless function — Phase 1.5 must not preempt that choice.
- **D-06:** Today there are zero `+page.server.ts` files (Pitfall 7 guard) so the deployed output is fully static in practice. No functions are invoked per request, cost stays at the free tier.

### Cache + security headers (netlify.toml [[headers]])
- **D-07:** Service worker must never be cached by the CDN — `/service-worker.js` gets `Cache-Control: no-cache` (or `public, max-age=0, must-revalidate`). This avoids the "stale SW installed forever" class of bugs.
- **D-08:** SvelteKit's `_app/immutable/*` bundle (content-hashed) gets `Cache-Control: public, max-age=31536000, immutable`.
- **D-09:** `/manifest.webmanifest` gets `Cache-Control: public, max-age=3600` (short, since manifest changes may need to propagate quickly).
- **D-10:** Manifest icons (`/manifest-icon-192.png`, `/manifest-icon-512.png`, `/apple-touch-icon.png`) get `Cache-Control: public, max-age=31536000` — when icons change we bump their filenames.
- **D-11:** CSP stays in `src/app.html` meta tag as the single source of truth. Do NOT mirror it as an HTTP header in netlify.toml — two copies drift; one copy is easier to maintain. Revisit if meta-based CSP proves insufficient against a specific attack vector (none anticipated for a local-only app).
- **D-12:** Skip `Service-Worker-Allowed` header. Our SW is at root (`/service-worker.js`) and controls `/` by default — no scope extension needed.

### Netlify site identity
- **D-13:** Site lives under the user's personal Netlify account, not a JobRad org account. Ownership portable across employment.
- **D-14:** Requested slug: `moodlog.netlify.app`. Fallbacks if taken: `moodlog-app.netlify.app`, `holgergp-moodlog.netlify.app`, or Netlify auto-generated. Plan should document the chosen final slug at execution time.
- **D-15:** Netlify project linked to GitHub repo `holgergp/moodlog` via OAuth. First-time link is a manual web-UI step (cannot be automated) — plan must flag this as a one-shot human-action checkpoint.

### Claude's Discretion
- Node version pinning mechanism (netlify.toml `[build.environment] NODE_VERSION` vs `.nvmrc` — both work; pick one and document).
- Exact build command (defaults to `npm run build`; override only if needed).
- `publish` directory (defaults to `build` for adapter-netlify).
- Log format in netlify.toml comments.
- Whether to add a `[[redirects]]` rule for SPA fallback — adapter-netlify handles this automatically, but verify during execution.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- **vite-plugin-pwa (SvelteKitPWA)** already configured in `vite.config.ts`. It already emits a valid service worker and manifest at build time. Phase 1.5 only needs to verify the output deploys with correct MIME types and cache headers.
- **svelte-kit build pipeline** emits to `.svelte-kit/output/` by default; adapter-netlify routes that to `build/` for Netlify to serve. No custom tooling required.
- **package.json scripts** — `build` and `preview` already defined. Netlify build uses `npm run build`.
- **tests/pwa.test.ts + tests/sw.test.ts** — both GREEN after Plan 05. Pre-deploy regression test is `npm run test`.

### Established Patterns
- **No `+page.server.ts` anywhere** (Pitfall 7). Plan 05's file-header comment explicitly documents the `onsubmit|preventDefault` client-side pattern. This gives us pure-client output regardless of which adapter shape we pick.
- **Dexie-only persistence** — no external service calls, no environment variables required for runtime behavior. Deploy env vars stay empty for now.
- **Copy contract** (`tests/copy.test.ts`) scans `messages/*.json` + source. Post-deploy verification should run the same tests against the deployed output if we have a way to run headless tests against prod URL. (Probably out of scope for Phase 1.5; local `npm run test` is enough.)

### Integration Points
- **`svelte.config.js`** — this is where `adapter-auto` gets swapped to `@sveltejs/adapter-netlify`. One-line change plus install.
- **`netlify.toml`** (new file at repo root) — `[build]`, `[[headers]]`, optionally `[[redirects]]`, optionally `[build.environment]` for Node version.
- **`package.json`** — `@sveltejs/adapter-netlify` devDependency. Possibly remove `@sveltejs/adapter-auto` if no longer referenced.
- **GitHub → Netlify OAuth** — one-time manual setup via Netlify UI. Plan must treat this as an explicit human-action checkpoint.

</code_context>

## Specific Ideas

- **Preview URL iteration loop:** push feature branch → Netlify deploys → test on `deploy-preview-*.netlify.app` → iterate. Each round ~2–3 min. The three HUMAN-UAT items drive how many rounds we need.
- **First PR = Phase 1.5's deliverable.** It includes the adapter swap, netlify.toml, docs, and a tested preview URL. After merge, production URL comes online.
- **Keep the preview URL scheme clean:** moodlog.netlify.app if available; otherwise holgergp-moodlog. User personally owns the site.
- **Don't touch manifest icons.** Plan 05 shipped neutral #FAFAF9 placeholders deliberately; branded artwork is a pre-v1-ship follow-up, not Phase 1.5 work.
